= Sample security policy

These samples retain Spring Boot 2.7.18 and Spring Framework 5.3.39 for compatibility.
Known vulnerabilities remain. The security scan contains documented exceptions for specific findings.
A passing scan does not mean these versions are free of known vulnerabilities.
Production deployments require a separate security assessment and appropriate patched dependencies.

== Compatible versions

As checked on 2026-10-09, Maven Central lists 2.7.18 as the latest public Spring Boot 2.7 release
and 5.3.39 as the latest public Spring Framework 5.3 release.
The Hibernate, Java and `javax` baseline stays the same.
https://docs.spring.io/spring-boot/docs/2.7.18/reference/html/getting-started.html#getting-started.system-requirements[Spring Boot 2.7.18 supports Java 8 and later].
The repository's separate Java 8 build limits still apply; these updates do not certify Java 8 operation.

https://repo.maven.apache.org/maven2/org/springframework/boot/spring-boot-dependencies/maven-metadata.xml[Boot BOM metadata]
and https://repo.maven.apache.org/maven2/org/springframework/spring-framework-bom/maven-metadata.xml[Framework BOM metadata]
provide the public version lists.

Spring lists enterprise fixes within these lines:

* https://spring.io/security/cve-2026-22733/[Boot 2.7.32] for CVE-2026-22733;
  https://spring.io/security/cve-2026-40972/[2.7.33] for the reported April Boot findings;
  https://spring.io/security/cve-2026-41001/[2.7.34] for CVE-2026-41001.
* https://spring.io/security/cve-2026-41855/[Framework 5.3.49] for the reported June findings;
  https://spring.io/security/cve-2026-47884/[5.3.50] for the reported August findings.

Boot 2.7.34 and Framework 5.3.50 are minimum fixes for the reported 2026 set,
not a claim about the latest enterprise releases or all known vulnerabilities.
These BOM versions were absent from Maven Central when checked.
An enterprise upgrade needs authorized repository access and a separate qualification.

== Scan policy

Run the normal Maven build with `-Powasp`. It runs Dependency-Check `check` for each module
at `verify`. Each module writes its own report under `target`.
The CVSS failure threshold remains 7. The existing provided, runtime and test scope exclusions remain.
The profile uses Dependency-Check 12.2.2 with its normal analyzer and automatic update settings.
This version automatically disables the Sonatype OSS Index analyzer when credentials are missing.
The gate can then pass without OSS Index results. A complete scan with OSS Index coverage still requires working credentials.

Library modules use only link:../src/main/config/dependency-check-suppression.xml[the shared suppression file].
The `samples` parent adds link:src/main/config/dependency-check-suppression.xml[the sample exception file]
for its descendants. Sample risk acceptance does not apply to released library modules.
Use the configured `check` goal, not a manually invoked reactor-wide `aggregate` goal,
to apply these two policies separately.

Each sample rule names one CVE and a finite list of exact Maven packages at one exact version.
The anchored package expressions list artifact names; they have no package or version wildcard.
Dependency-Check can merge related JARs and report the same CPE against any member of that set.
The rules list only packages identified in the resolved sample scans. They match NVD CVE IDs
and named analyzer findings. No Spring library or CPE is excluded from scanning.
New CVEs, other packages and changed versions stay visible.
The rules expire at 00:00 UTC on 2027-01-07, 90 days after review.
Review each advisory, dependencies, packaged JARs and application configuration before that date.
Do not extend a rule without a new assessment. Reassess sooner if sample code or configuration changes.

== Findings and decisions

The inventory includes the Spring findings from Actions run
https://github.com/coherence-community/coherence-hibernate/actions/runs/37776381152[37776381152],
the retained cached scan, and the remaining historical Spring exceptions.
The old `spring-core` finding was for 5.3.31; these rules use the resolved 5.3.39 version.
Per-module scans can report these known CVEs against related JARs with the same CPE.
The exception expressions name each such Maven artifact and its exact version.

`Inapplicable` means an advisory condition is absent from the checked sample code,
configuration or packaged JARs. It does not mean the dependency has been patched.
`Accepted risk` means vulnerable code remains and applicability is possible or uncertain.
No smoke test establishes security inapplicability. Deployments with different dependencies,
configuration or code must repeat this assessment.
The exact package list for each decision is in the sample exception file.

The historical global Spring rules were removed. CVE-2024-22259 was fixed in 5.3.33,
and CVE-2024-38808 was fixed in 5.3.39; they need no exception for this baseline.
The https://spring.io/security/cve-2025-41234/[CVE-2025-41234 advisory] lists affected 6.x versions,
not 5.3.39, so its global exception was removed without replacement.
Remaining historical Spring exceptions now have exact sample package and version limits.
The shared Hibernate Validator exception for CVE-2025-15104 remains a documented product mismatch:
the https://github.com/CVEProject/cvelistV5/blob/main/cves/2025/15xxx/CVE-2025-15104.json[CNA record]
concerns Nu Html Checker. It also has a finite review date.
Other historical non-Spring exceptions are unchanged and are outside this policy review.
