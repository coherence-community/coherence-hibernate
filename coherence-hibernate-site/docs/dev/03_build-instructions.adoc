= Building
:description: Oracle Coherence Hibernate Website
:keywords: coherence, hibernate, java, documentation

// DO NOT remove this header - it might look like a duplicate of the header above, but
// both they serve a purpose, and the docs will look wrong if it is removed.

To build the Coherence Hibernate project you need to have the following software installed:

- https://www.oracle.com/java/technologies/downloads/[Java SE Development Kit 17, 21, or 25].
- http://maven.apache.org/[Apache Maven]

Once you have these installed building the entire source tree is as simple as executing the following shell command
(from the root of the source directory):

[source,bash]
----
./mvnw clean package
----

The parent POM defaults to Hibernate `7.4.10.Final` and Coherence `15.1.1-0-5`; Java 17 remains the bytecode baseline.
The GitHub Actions workflow configures this default reactor on Java 17, 21, and 25. Its `main` compatibility job
configures Hibernate `7.4.1.Final`, `7.4.5.Final`, and `7.4.9.Final` against Coherence `15.1.1-0-5` and `26.07` on
Java 17, and against `26.10-SNAPSHOT` on Java 21 with explicit hardened mode.

To exercise the development snapshot locally, select JDK 21 through `JAVA_HOME` and `PATH`, then run:

[source,bash]
----
./mvnw --settings .mvn/coherence-snapshots-settings.xml \
  -Dcoherence.version=26.10-SNAPSHOT -Dcoherence.security.mode=hardened \
  -pl coherence-hibernate-cache-7,coherence-hibernate-cache-store-tests -am test
----

This uses the default Hibernate `7.4.10.Final`; add `-Dhibernate7.version=<version>` to select a compatibility version.
The settings file checks for updated snapshot metadata on every Maven invocation. Both snapshot repositories
disallow releases; the plugin repository also supplies the sample's snapshot security-config Shade transformer.
Locally installed snapshots can still take precedence.
To test published artifacts without local installations, select an empty, dedicated Maven repository with
`-Dmaven.repo.local=/path/to/temporary-repository`, and remove that repository when finished.

CI supplies these settings only to snapshot compatibility legs. Each leg discards only the restored
`com.oracle.coherence.ce:coherence:26.10-SNAPSHOT` cache directory before testing, so it resolves the latest published
snapshot independently. Cache keys and restore prefixes separate the default build from compatibility jobs and
separate JDK/Hibernate/Coherence combinations; POM and `.mvn` changes invalidate the exact cache key.

A publication during the workflow can change the snapshot between jobs. This policy keeps a current development
signal rather than pinning a qualification build, and a later rerun may resolve different bytes.

The tested snapshot requires Java 21, while the adapter still targets Java 17. Compatibility jobs still stop at
`test`; the default reactor's `verify` includes the packaged security checks. Snapshot tests do not qualify released
`26.10` or later binaries, and a configured workflow does not establish a completed hosted run or deployment qualification.

For detailed instructions, please see the main
https://github.com/coherence-community/coherence-hibernate/blob/main/README.adoc[README] of the Coherence Hibernate
source code repository.
